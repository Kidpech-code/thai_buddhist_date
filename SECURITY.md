# Security Policy

## Supported versions

Security fixes target the latest published version of each package. Older
versions may receive a fix when the issue is severe and a backport is practical,
but this is not guaranteed. Users should upgrade to the latest compatible
release before reporting a problem.

## Reporting a vulnerability

Do not open a public issue containing exploit details, credentials, personal
data, or an unpatched vulnerability.

Use GitHub's private vulnerability reporting for this repository:

https://github.com/Kidpech-code/thai_buddhist_date/security/advisories/new

Include the affected package and version, impact, reproduction steps, proof of
concept if safe, and any suggested mitigation. Remove unrelated secrets and
personal data.

If private reporting is unavailable, contact the maintainer through the contact
method on the [Kidpech-code GitHub profile](https://github.com/Kidpech-code) and
share only enough public information to establish a private channel.

The maintainer will acknowledge a complete report as soon as practical,
validate its severity, coordinate a fix and release, and credit the reporter
when requested and appropriate. Please allow time for a fix before public
disclosure.

## Scope

Security issues include malicious or unexpected code execution, supply-chain or
publishing compromise, unsafe parsing that causes a material availability or
integrity impact, and accidental exposure of sensitive data. General correctness
bugs without a security impact belong in the public issue tracker.
